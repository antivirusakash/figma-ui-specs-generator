# Core Design Philosophy

> **Pairs with**: [Rules/core.md](../Rules/core.md)
> **Load when**: Always (foundational knowledge)

---

## Core Beliefs

| Belief | Implication |
|--------|-------------|
| Day 30 > Day 1 | Optimize for repeated use, not first impression |
| Familiar > Novel | Copy existing patterns; innovation is overrated for utility |
| Unhappy path > Happy path | Design errors first; success takes care of itself |
| Cognitive load > Click count | 10 easy clicks beats 3 confusing ones |
| Users scroll | If content earns it; boring content is the problem, not scroll |

---

## Designer's Forcing Functions

| Constraint | Rationale |
|------------|-----------|
| If I can't name a component, it doesn't ship | Naming forces clarity of purpose |
| Max 2-3 font weights per view | Forces typographic discipline |
| Every color must have semantic meaning | No decorative color without purpose |
| Can explain every element's purpose | Nothing decorative without function |

---

## Contrarian Wisdom

| Common Belief | Actually True |
|---------------|---------------|
| "Users don't scroll" | They do — if content earns it |
| "Fewer clicks is better" | Cognitive load matters more than click count |
| "Make it innovative" | Make it boring — boring is more usable |
| "Design the happy path" | Design the unhappy path — success takes care of itself |

---

## Underrated Aspects

These get too little attention in most teams:

1. **Copy and microcopy** — Words are UI; they deserve design time
2. **Error states and failure modes** — Happy path gets 90% of attention
3. **Onboarding and empty states** — First impression of every feature
